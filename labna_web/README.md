# Labna Web

مرحلة المشروع الحالية: **تنفيذ أساس API والكتالوج والفروع وإدارتهما**.

## المنفّذ الآن

- Express 5 + TypeScript + Mongoose، مع health endpoints وإيقاف منظم للسيرفر.
- قراءة المنتجات والأقسام والبنرات والفروع وإعدادات المتجر.
- البحث والتصفية والترتيب وpagination وETag/304.
- CRUD إداري مع الأرشفة وversion checks ومعاملات تمنع تعارض مراجع الكتالوج.
- حساب مدير، Argon2، access tokens، refresh cookies دوارة وإبطال الجلسات.
- إنشاء صفوف مخزون بصفر وحساب التوفر حسب الفرع، دون تعديل جرد أو طلبات بعد.
- حساب مواعيد الفروع والاستثناءات اليومية بتوقيت الفرع.
- Zod validation، أخطاء موحدة، CORS، rate limiting، وسجل تدقيق للتعديلات.
- OpenAPI 3.1 حي على `/api/v1/openapi.json` مشتق جزئيًا من schemas المستخدمة فعليًا.
- اختبارات تكامل باستخدام MongoDB replica set مؤقت حقيقي، وليس mock لقاعدة البيانات.

**الواجهات المرئية للمتجر ولوحة التحكم، حسابات العملاء، OTP، الطلبات، تعديلات الجرد، رفع الصور والإشعارات هي المراحل التالية.** حاليًا الصور روابط HTTPS من `MEDIA_ORIGINS`؛ تكامل ملكية الصور ورفعها إلى Cloudinary لم ينفذ بعد.

## التشغيل المحلي

نفّذ الأوامر التالية من مجلد `labna_web`:

```bash
nvm install
nvm use
npm ci
docker compose up -d --wait
cp apps/api/.env.example apps/api/.env
```

يتطلب المشروع Node.js 22.12+ من سلسلة 22 LTS أو 24+. تم الاختبار على Node.js 22.23.3. ملف Docker للتطوير المحلي فقط، وقاعدة البيانات مقيدة بمنفذ localhost. يمكن استخدام MongoDB Atlas بدل Docker؛ حدّث `MONGODB_URI`.

عدّل `apps/api/.env`:
- ولّد `JWT_SECRET` و`CURSOR_SECRET` بشكل مستقل باستخدام `openssl rand -hex 32` لكل منهما.
- حدّد `SEED_ADMIN_EMAIL` و`SEED_ADMIN_PASSWORD` (12 حرفًا على الأقل).
- اضبط `MEDIA_ORIGINS` على مضيف صورك و`WEB_ORIGINS` على أصول واجهاتك.
- لا ترفع `.env` إلى Git؛ هو مستثنى بالفعل.

```bash
npm run seed
npm run dev
```

seed ينشئ المدير وإعدادات المتجر فقط؛ لا يغير كلمة مرور حساب موجود ولا يضيف منتجات أو مخزونًا وهميًا. لا يوجد حساب أو كلمة مرور افتراضية. المنفذ الافتراضي `3001`.

```bash
curl http://localhost:3001/health/ready
curl http://localhost:3001/api/v1/store
curl http://localhost:3001/api/v1/openapi.json
```

خطوات إعداد كتالوج من الصفر باستخدام Postman أو أي عميل HTTP موضحة في [دليل التشغيل](docs/implementation.md).

## التحقق والبناء

```bash
npm run typecheck
npm test
npm run build
npm audit
npm run start -w @labna/api
```

الاختبارات تستخدم قاعدة معزولة مؤقتة ولا تتصل بـ`.env`. أول تشغيل قد يحتاج تنزيل MongoDB binary. `npm run openapi --silent` يطبع وثيقة OpenAPI إلى stdout.

ملف `package-lock.json` مثبت في المشروع. استخدم `npm ci` للتثبيت المتكرر؛ إذا واجه npm 10 خطأ `edgesOut` عند ترقية dependencies فاستخدم npm 11 مع Node LTS.

## النطاق المعتمد

- متجر ويب بتخطيط مكتبي متجاوب، وهوية لبنة، ووظائف متوافقة مع تطبيق iOS.
- الاستلام من الفرع فقط، والدفع عند الاستلام، دون توصيل أو حجز موعد.
- فرع استلام واحد مبدئيًا؛ إدارة عدة فروع وتفعيل الاستلام منها لاحقًا.
- مخزون لكل خيار منتج ولكل فرع، وأسعار وكتالوج موحدان.
- تصفح وسلة محلية دون حساب؛ تأكيد الطلب بعد الدخول برقم الهاتف.
- كود تحقق ثابت للتطوير فقط، واستبداله بمزوّد SMS للإطلاق الحقيقي.
- مزامنة المفضلة والمشاهدات، وسلة مستقلة لكل جهاز.
- إلغاء العميل قبل تأكيد الموظف فقط.
- قبول الطلبات خارج مواعيد العمل مع إعلام العميل بأنها تُعالج عند الفتح التالي.

## الهيكل الحالي والخطة

```text
labna_web/
  apps/
    api/          # Node.js, Express, TypeScript, Mongoose
    storefront/   # مخطط: Next.js / React
    admin/        # مخطط: React / Vite
  packages/
    contracts/    # مخطط: تُنقل له contracts.ts عند بناء واجهات React
  docs/
```

MongoDB replica set مطلوب للمعاملات، حتى في بيئة التطوير. السيرفر يتحقق من هذا الشرط عند بدء التشغيل. schemas الحالية في `apps/api/src/contracts.ts`، وتوثيق OpenAPI في `apps/api/src/openapi.ts`.

## مراحل التنفيذ التالية

2. الكتالوج والفروع والصور ولوحة إدارتهما، ثم ربط iOS عبر adapter.

4. المخزون والطلبات ومعاملات الحجز والإلغاء والتسليم.

وثيقتا التصميم تصفان الخطة الكاملة؛ OpenAPI الحي يصف المسارات المنفّذة فقط. التفاصيل والحدود المرحلية موثقة في `docs/implementation.md`.
